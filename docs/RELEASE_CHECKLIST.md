# Release maintenance

For each software release:

1. Run the unit tests, offline demo and applicable engine integration tests.
2. Pin engine source revisions and retain environment/dependency records.
3. Update the software version, changelog and citation metadata.
4. Tag the tested commit and publish a release containing the source archive and checksum manifest.
5. Cite the released version in publications; add an archival DOI when one has actually been minted.

Experiment-specific reproduction packages should additionally include shareable target structures, explicit residue maps, scientific settings, model hashes, seeds and expected outputs. Preserve third-party attribution and access conditions. Manuscripts and private working records are maintained outside this code repository.
